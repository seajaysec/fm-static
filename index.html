fm-static

Firmware installer for the M-VAVE FM-1

fm-static installs a .fwsc firmware file on an M-VAVE FM-1. Use it when you're finding it hard to get your FM-1 to flash through other means. Bring a .fwsc file and follow the process through to the end.

It is made for the M-VAVE FM-1. The SMK-37 may work; that is completely untested. It checks that the FM-1 comes back running what you installed, not how it sounds.

Do I need official V15 first?

Choose the firmware you want to end up with. FM-Static checks the file and the device’s current state instead of imposing a blanket V15 prerequisite. When a supported route needs an intermediate step, the page handles it: optional cleanup runs V15 temporarily to prepare saved data, then installs your chosen firmware. An official-firmware refusal can use a different, compatible temporary updater. The device must accept each pass and return the expected identity before the next step starts.

If you want V15: Download official V15 (.fwsc, archived copy). Then choose the downloaded file in Firmware file. This is the original M-VAVE package; the manufacturer’s current download URL now serves V16.

          FM-1 still missing? Check USB recovery mode

          If normal firmware cannot start, the FM-1 may appear as a USB recovery device instead of a MIDI instrument. This is the chip’s built-in ROM download mode, sometimes called “boot mode”; it is different from the MIDI update mode used while flashing.

          How to enter recovery mode and what to do next. The button combination depends on the firmware or bootloader installed.

          Where WebUSB is available, the check below opens a USB device picker and only identifies the selected device. It does not switch modes or write firmware. A missing MIDI port alone does not mean the FM-1 needs recovery.

            1. OPTION
              Install through a temporary updater

              Some community updaters reject official firmware when startup code has changed—for example after installing m-bootloader. We can read the running firmware’s identity, but cannot tell from it which bootloader is installed. Try a normal install first; use this route if needed.

              Pass 1 installs the generic fm1-base template 0.3, preserving startup code. Once it answers, pass 2 installs your selected firmware. Your selection stays loaded. No extended wipe or m-bootloader installation is added.

              This replaces the running application temporarily and can affect saved data. Official firmware then replaces the bootloader. Tested on an FM-1 returning from Optimist 0.2 synths with m-bootloader to verified V15; other starting builds remain unverified. Keep this page open through both passes; reloading loses its recovery state.

              Requires the backup acknowledgement below and only one responding FM-1. Disconnect other FM-1s first. The temporary file is fetched from a pinned upstream revision and checked by SHA-256 before either pass begins.

            2. OPTION
              Application/data cleanup

              Usually unnecessary—try a normal install first. This optional extended wipe is offered for convenience and may be worth trying if a normal flash fails.

              The extra voice-region step uses the factory data recovered by KingParamount, pinned and checked before cleanup starts. Source licence.

            3. OPTION
              Also install m-bootloader

              Returning to official firmware later can be refused by an older community updater because m-bootloader changes startup code. Install through this page’s temporary updater, or use M-Flasher, if that happens. A normal official update replaces m-bootloader.

              An open bootloader by Julius Vitkauskas (MIT). It replaces M-VAVE's bootloader and stays through application-only updates. Hold PLAY while switching on for a recovery menu, or REC for USB download mode used by desktop recovery tools, even when a firmware won't start. It is written after the firmware, and the FM-1 restarts once more for it. It rewrites the FM-1's startup code (the first 16 KB of flash), the one region a failed write can leave unbootable. A firmware that does not know m-bootloader's installer refuses it and nothing is written. Installing an M-VAVE package afterwards puts M-VAVE's bootloader back.

            4. BEFORE
              Before you install

              Installing can lose what your FM-1 has saved. If the firmware on your FM-1 has its own backup utility, consider using that now.

              While it writes, the FM-1's screen shows UPDATING and a bar, or stays dark. Don't unplug the cable or switch the FM-1 off until this page says Done. It can take a few minutes.

            After a fresh device check, select the same FM-1 used for this sequence. Disconnect other FM-1s before continuing. The protocol cannot identify a unit by serial number.

            Completed passes stay installed. Cancellation is available once normal firmware answers.

              1. RESTORE

                Restore official startup code

                If you installed m-bootloader separately, a normal firmware file usually cannot supply the startup bytes now on your device. Try Install through a temporary updater above before this workaround.

                Return to stock through a compatible updater: use Install through a temporary updater above. It installs the generic fm1-base template first, then your selected official firmware. This completed on an FM-1 after reproducing the four-request V15 refusal with Optimist 0.2 synths and m-bootloader. Installing V15 normally replaces m-bootloader with M-VAVE’s bootloader. M-Flasher is the desktop alternative.

                The firmware on your FM-1 refused this package at the startup-code check. This mode answers that check with the startup code your FM-1 already has, taken from a Felucca-family file you pick, so the check passes. Then M-VAVE's loader writes the package, its own startup code included.

                This part carries real risk. Here is what, and why.

                • It rewrites the one region a failed write can leave unbootable. The first 16 KB of flash holds the code that starts the update loader. Felucca's own loader leaves it alone. If power or USB drops while it is being rewritten, the FM-1 may not start.
                • This page cannot recover it. If a write is cut off badly, the FM-1 may stop starting and fall back to the chip's ROM boot mode (WL80UBOOT, USB 4C4A:8057), which does not depend on that flash. This page can recognise that state (the "boot mode" button under Your FM-1) and point you to an open tool, but it cannot write from there, and that way back has not been tested. Treat this mode as one with no undo.
                • This workaround is not device-tested. Its startup-byte substitution passes a host simulation. Successful normal installs and guided cleanup test different routes; they do not validate this separate check bypass.
                • This package can overwrite saved data. Its flash.bin is larger than V15's, so the loader also overwrites flash above 0x93000, where Felucca-family firmwares keep saved projects. V15 itself stops at 0x93000 and leaves them.
                • It can also do nothing. If the file you pick does not carry the startup code that is on your FM-1, the firmware refuses again and nothing is written.

                Lower the odds: USB straight into the computer, laptop on power, this tab in front the whole time. If the write is cut off while the FM-1 is in update mode, replug it and press Finish update.

                Backup and recovery tools
                
    
                Use the tool that matches the state your FM-1 is in. These are separate projects; follow their current instructions.
                
    
                
      
                Normal update
                M-UPGRADE — M-VAVE's official updater for Windows and macOS. It is documented for firmware updates; raw flash backup support has not been verified.
                
      
                Backup or ROM recovery
                M-Flasher — the recommended desktop route for full-flash backup, backup restore and ROM download-mode recovery on Windows, macOS and Linux. Start with its backup action.
                
      
                Command-line recovery
                MvaveFM1Unbricker — a Windows/Linux alternative for an FM-1 visible as WL82 UBOOT1.00. It makes a double-read backup and verifies application-area writes. Its direct USB recovery backend does not support macOS; check its package restrictions before using it.
                
      
                Bricked FM-1
                FM-1 Transporter — recovery through an extra RP2040/RP2350 board wired to the USB data lines. It has its own Chrome/Edge web app over serial. Hardware and setup are required; this page does not control it.
                
    
                
    
                A firmware's own project export is different from a full-flash backup. Layout Analysis accepts a raw 1 MiB .bin file; it cannot restore it. These external recovery paths have not been tested on a device as part of this page.
                
    
                
      
                Get back to working firmware
                
      
                
        MIDI still answers, or an update was interrupted
        
                If the update loader answers, keep the same firmware file loaded and use Finish update. For a two-pass operation, keep this page open so it retains the package for the interrupted pass.
                
        
                If normal firmware answers but refuses V15 after four requests, try Install through a temporary updater on Flash. m-bootloader alone does not determine whether an update is accepted: the running firmware’s updater matters. You do not need ROM download mode for that route.
                
        
                Optimist only: if the application will not start, hold OCT− alone while switching on for its USB rescue screen, then reconnect to a MIDI installer. This is an application rescue mode, not ROM download mode. Optimist’s recovery instructions.
                
      
                
      
                
        No MIDI reply: enter ROM download mode
        
                Use the method for what is installed. There is no universal FM-1 button combination.
                
        
                  
          
                • Working stock or Felucca firmware: use M-Flasher’s DOWNLOAD MODE action over USB MIDI.
                  • 
          
                • m-bootloader installed: hold REC while switching on. Holding PLAY instead opens its recovery menu.
                  • 
          
                • Felucca, SLOOP or Snoop37 running: hold OCT− and OCT+ for 5 seconds.
                  • 
          
                • Optimist installed: its instructions specify holding OCT− and OCT+ while switching on, for 3 seconds. Do not apply that shortcut to other firmware.
                  • 
        
                
        
                Connect directly with a USB data cable. The computer may see WL82 UBOOT1.00, with no usable drive in Finder or Explorer; the display can stay dark or unchanged. On macOS, open M-Flasher promptly: the disk driver may make the device leave download mode after about 30 seconds.
                
        
                If these methods cannot reach it, use the external hardware recovery routes above. M-Flasher’s current instructions · m-bootloader controls.
                
      
                
      
                
        Once M-Flasher finds it
        
                  
          
                1. Check the detected model and Back up the whole flash before changing anything. Keep the resulting files.
                  2. 
          
                2. Choose Install firmware (.fwsc) or restore a suitable backup. Review the bootloader and erase options; they change what is written.
                  3. 
          
                3. Wait for writing and verification to finish. Then unplug, switch off and on, and reconnect.
                  4. 
          
                4. To check the running firmware here, return to Flash, load its package, connect and use Refresh devices. The firmware identity matters more than the cached MIDI port name.
                  5. 
        
                
      
                
      
                
        V15 runs, but its presets sound wrong
        
                A successful firmware install is not a factory reset. Community firmware such as Optimist uses storage that V15 expects to hold its voice banks. Installing V15 alone leaves that sound data in place.
                
        
                The optional Application/data cleanup route uses V15 as a temporary maintenance step. It applies valid data to the 16 KiB saved-voice region, then continues to your chosen firmware.
                
        
                This replaces all 128 stored voices and also erases below 0xBA000. The extra region at 0xEA000–0xEE000 overlaps sequence data and Bluetooth pairings in V16. It does not reset the whole flash or every setting.
                
        
                M-VAVE’s Open Workbench is an alternative for the bank set embedded in the official firmware package.

                The manufacturer and current Felucca installer also check the returning firmware identity and offer interrupted-update retries. FM-Static’s Finish update path is implemented but not yet device-tested. Its extra help includes selectable ports, guided intermediate installs, automatic data cleanup when selected, and explanations for known refusals. The separate startup-code restore remains an untested workaround.
                
      
                
        
                About the V15 gate. Choose the firmware you want to end up with. FM-Static checks the connected device and package instead of imposing a blanket V15 prerequisite. When optional cleanup needs V15, the page installs it temporarily and continues to your selection. A refused official package can use the separate temporary-updater route. These steps depend on the process and device state; the device can still refuse a pass.
                
        
                Where the browser stops. This page can inspect a raw backup but cannot read or restore the device’s whole flash. Whole-flash reset is not implemented. The current MIDI updater does not provide the native flash access used by desktop recovery tools. Transporter uses a separate hardware bridge and its own app. Choose a backup or recovery tool.
                
      
                
      
                Device-tested routes and limits
        
                  
          
                • Direct stock return: LOOM-8 0.9 with m-bootloader 1.2 accepted official V15 directly.
                  • 
          
                • Refused stock return: Optimist 0.2 synths with m-bootloader refused ordinary V15 after four requests. The guided temporary-updater route completed the return to V15.
                  • 
          
                • Cleanup: with 386DX FM-1_3860070 selected, Optimist 0.2 synths with m-bootloader reached temporary V15, acknowledged all four data-bank writes, then completed the wipe and 386DX install. Starting on V15 also completed data cleanup and installation of Optimist 0.2.
                  • 
        
                
        
                These are specific releases and paths, not a promise for every firmware. The final identity was verified and rediscovered automatically. Data acknowledgements are not readback or sound verification. Interrupted-update completion and the separate startup-code restore remain untested on hardware.
